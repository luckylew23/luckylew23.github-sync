# GitHub 同步（GitHub Sync for Textus）

在 Textus 打开的文件夹与 GitHub 仓库之间双向同步：保存时推送、定时拉取、逐文件解决冲突。

## 工作原理

Textus 插件运行在沙箱里没有 git，所以插件直接使用 GitHub 的 [Git Database REST API](https://docs.github.com/en/rest/git)。这保证一次同步就是一个原子提交：文件上传为 blob，在当前远端树上叠一棵新树，一个提交指向它，分支引用最后一步才移动——同步到一半的产物永远到不了远端。

为了不下载任何内容就能知道什么变了，插件在本地计算每个文件的 blob SHA（`sha1("blob " + 长度 + "\0" + 内容)`），与远端树和上次同步记录的 SHA 做三路比较：

| 本地 vs 基准 | 远端 vs 基准 | 结果 |
| --- | --- | --- |
| 未变 | 变了 | 拉取 |
| 变了 | 未变 | 推送 |
| 都变了且不同 | | 冲突，逐文件解决 |

只传输变化的文件，所以大文件夹的第二次同步只需少量请求。

## 设置

1. 创建一个带 `repo` 权限的[个人访问令牌](https://github.com/settings/tokens)。
2. 打开 GitHub 同步面板（设置 › 扩展，或状态栏图标）。
3. 粘贴令牌，选择或新建仓库，选择分支。
4. 如果文件夹和仓库两边都有内容，选择以哪边为准。

令牌存在 Textus 的安全存储里，不会离开。仓库和设置按文件夹保存在 `.textus/plugins/`。

## 同步

- **自动推送**：每次保存启动 5 秒防抖；安静下来后推送。可在面板的设置区关闭。
- **自动拉取**：每 5 分钟一次，且只在没有待推送内容时执行。
- **冲突**：面板列出每个冲突文件，三个选择——保留本地、保留远端、两者都留（远端副本存为 `名字 (remote).扩展名`）。

## 同步范围

打开文件夹里的所有文件，除了：以点开头的文件夹（`.textus`、`.git` 等）、`.gitignore` 匹配的内容、大于 10 MB 的文件。

## 限制

- 仅支持 GitHub（Gitee/Gitea 的 API 不同）；不浏览 git 历史，请用 github.com。
- 每个文件夹一个分支；跨分支合并不在范围内。
- 单文件 10 MB 上限，防止误同步大文件。
