# GitHub 同步（GitHub Sync for Textus）

把 Textus 打开的文件夹同步到 GitHub 上的一个普通仓库：文件保持原来的路径，**一次同步就是一个提交**，GitHub 上看到的就是文件夹里的样子，可以直接在网页上翻、搜索、看历史。

跟 Textus 官方的 cloud-sync 插件互不影响，可以同时装：那个插件管 WebDAV、坚果云、S3 和加密分块，这个只管 GitHub，写的是真实文件，没有加密块，也没有 manifest。

## 它是怎么做的

Textus 插件里没有 git，所以这个插件直接走 GitHub 的 [Git Database REST API](https://docs.github.com/en/rest/git)：文件传成 blob → 在远端当前树上叠一棵新树 → 一个提交指向它 → 最后一步才移动分支引用。同步到一半失败，远端什么都不会变（没有半步提交）。

为了不下载内容就知道哪儿变了，插件在本地算每个文件的 blob 哈希（`sha1("blob " + 长度 + "\0" + 内容)`），和远端树、和上次同步记下的哈希做三方比较。只有变化的文件才传输，所以第二次同步通常只有几个请求。

## 同步规则（本地 × 远端）

| 这个文件夹 | GitHub 上 | 同步做什么 |
| --- | --- | --- |
| 没变 | 没变 | 什么也不做 |
| 新增 | 没有 | 上传 |
| 改了 | 没变 | 上传 |
| 没变 | 新增 | 下载 |
| 没变 | 改了 | 下载 |
| 没变 | 删了 | **找回来**（设置里可改成"本地也删"） |
| 改了 | 删了 | 冲突 |
| 删了 | 没变 | 在 GitHub 上删掉 |
| 删了 | 改了 | 冲突 |
| 新增 | 新增（两边同一路径、内容不同） | 冲突（只在首次连接时出现） |

几条刻意定下的原则：

- **删除只从本地往外走。** 插件永远不会自己清空文件夹；GitHub 上被删的文件会恢复回来，除非删除是你在本机做的。一个"镜像"自己把工作区清空过一次，就是因为反过来做。
- **冲突不猜。** 两边都改过的文件默认留在原地等你决定（面板里逐文件三选一）；设置里也可以固定成"保留本地""采用 GitHub 的""两边都留"。
- **两边都留**时，GitHub 的版本存成 `名字 (conflict 20261126-040506).扩展名` 放在同一个提交里，谁都不丢字节。
- **首次连接**：文件夹和仓库都有内容时，先问以哪边为准（或者选"只发""只收"），不会悄悄覆盖任何一边。

## 同步范围

不按文件类型过滤——Markdown、图片、PDF、`.html`、`.json` 都同步。只看两件事：

1. **规则**：面板里的规则框，每行一条，写法和 `.gitignore` 一样——路径、以 `/` 结尾的文件夹、`*`/`?`/`[...]` 通配，行首 `/` 锚定到文件夹顶层，行首 `!` 把排除的内容重新包含进来。默认规则排掉 `node_modules/`、各种构建目录和系统文件。
2. **大小上限**：默认 20 MB，可以按 MB 调整；插件自己的硬上限是单文件 32 MB（Textus 的插件桥一次最多接收 32 MB 的响应），GitHub 的上限是 100 MB。超过上限的文件留在本机，面板会列出它们是哪些。

`.git` 和 `.textus` 永远不同步（规则也改不了），因为前者会让插件读到自己的提交、后者是插件自己的数据。

## 设置

1. 建一个[细粒度令牌](https://github.com/settings/tokens?type=beta)，给目标仓库 **Contents: read and write** 就够；用经典令牌则勾 `repo`。
2. 打开面板（侧栏的 GitHub 标签页；或命令面板里的「GitHub 同步：打开」）。
3. 粘贴令牌 → 选已有仓库或新建 → 选分支 → 开始同步。
4. 两边都有内容时，选择以哪边为准。

令牌存在 Textus 的 secret 存储里，只在这台电脑上，永远不写进仓库；断开连接可以把它删掉。仓库和上次同步的哈希记在这个文件夹的 `.textus/plugins/luckylew23.github-sync/` 里。

## 自动同步

- **保存后推送**：保存后先等几秒（默认 5 秒，可调），把这段时间的改动合成一个提交。
- **定时拉取**：默认每 5 分钟一次，且只在本机没有待推送内容、也没有未决冲突时才拉——否则会自己跟自己打架。
- 面板上的「立即同步」按设置里的方向走（双向 / 只发 / 只收）。

## 限制

- 只有 GitHub。要同步到坚果云、WebDAV、S3，用官方 cloud-sync 插件；这个插件保留同一个 provider 分层，将来可以加，但现在只发 GitHub。
- 一个文件夹对一个仓库的一个分支，跨分支合并不在范围内；想看历史请到 github.com。
- 仓库太大时 GitHub 会截断一次列树（10 万条），插件会报错让你收窄规则，而不是悄悄少同步。
- 平台只支持桌面端（Windows、macOS、Linux）；iOS 上没有文件系统的写入权限。

## 开发

- `host.js`、`panel.js` 是单文件、无构建步骤（这是插件市场的硬性要求：仓库和 zip 之间不能有构建），面板用 `textus-resource:` 引用同目录的 `panel.css`/`panel.js`。
- 纯逻辑——规则解析、三方比较、冲突策略——在 `host.js` 末尾导出，用 Node 跑测试：`node --test`。
- 发版：`git tag v0.2.0 && git push origin v0.2.0`，工作流会打 zip（`luckylew23.github-sync-0.2.0.zip`）发到 release。
